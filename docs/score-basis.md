# 比分口径审计：90 分钟 vs 含加时（2026-07-19）

## 数据事实

| 源 | 口径 | 覆盖 |
|---|---|---|
| `data/results.csv`（martj42） | 淘汰赛比分**含加时、不含点球**；小组赛/联赛制=90 分钟 | 全部国际赛 1872–2026 |
| `data/shootouts.csv`（martj42） | 点球大战场次登记（这些场 120' 平局，90' 也是平局） | 1967–2026，682 场 |
| `data/fjelstul_matches.csv` | 世界杯专库，带 `extra_time` / `penalty_shootout` 标记 | 世界杯 1930–2022，1248 场 |
| `data/jc_review.json` | **手填 90 分钟比分**（含补时，不含加时点球） | 用户录入 |

## 哪些训练场次口径不确定（审计数字，2026-07-19 实测）

- 已知打过加时的场次（`data.known_et_mask`）：全库 **714** 场；
  近 16 年训练窗（max_age=16y）内 **276 / 15568 ≈ 1.8%**。
- 其中两类：
  1. **点球场次**（shootouts.csv，占大多数）：90' 与 120' 都是平局 → W/D/L 训练标签
     **正确**，仅比分可能含加时进球（轻微抬高进球数）。
  2. **加时分胜负场次**（fjelstul ET=1 且无点球，世界杯 1930–2022 共 46 场）：
     results.csv 记为『胜』，90 分钟真实结果是平局 → **90 分钟标签错误**。
- **诚实边界**：非世界杯赛事（欧洲杯/美洲杯等）『加时分胜负、未到点球』的场次
  没有可靠公开源可识别，**不在掩码内**。我们**不推造 90 分钟比分**。

## 核心训练目标的真实口径（结论）

核心 DC 模型训练目标 = **全场比分（不含点球；淘汰赛历史样本含加时进球）**。
由于 ≈98% 训练样本是小组赛/预选赛/友谊赛（天然 90 分钟），模型输出**近似**
常规时间比分分布，但不是『严格 90 分钟』——文档/UI 一律使用『≈常规时间口径，
淘汰赛历史样本含少量加时』的表述，不再写『严格 90 分钟』。

## 剔除已知加时场次的 A/B 回测（bt_et90.py）

as-of 截断（cutoffs 2023-06/2024-11/2025-08，horizon 270d，hl=730），同一测试集
n=2344，训练集剔除 known_et 714 场 vs 全量（2026-07-19 实测）：

| 配置 | RPS | LogLoss | Acc |
|---|---|---|---|
| 全量（现行） | **0.1664** | **0.8538** | 0.595 |
| 剔除已知加时 | 0.1666 | 0.8552 | 0.595 |

ΔRPS = **+0.00023（剔除更差）**，远低于采纳门槛 0.0008 且方向为负收益 →
**维持全量训练**。口径差异（≈1.8% 样本含加时进球、46 场历史 90' 标签错误）
如实记为已知限制，不引入未经证据支持的改动。

## 下游口径规则（锁定）

- 竞彩复盘（jc_review）：**只用手填 90 分钟比分**结算 cover，绝不复用 results.csv
  （代码 + 测试双重锁定）。
- 淘汰赛晋级概率：模型 90'≈常规时间 W/D/L + 平局后加时/点球近似（见 simulate._padv
  与 docs 中的晋级近似说明）。
- 验证账本（verify）：按含加时口径的 results.csv 对账（与训练同口径，自洽）；
  竞彩 90 分钟对账走 jc_review，两套账本不混。
